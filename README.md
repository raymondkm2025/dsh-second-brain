# dsh-second-brain · 第二大脑

给 DeepSeek Harness 装一个本地「第二大脑」：**对话结束自动把值得复用的内容沉淀成本地 Markdown 知识卡**，配上自研去重、CJK 检索与可 git 管理的仓库，并在设置页提供**图形化知识库**与**交互式知识图谱**。

没有数据库，没有云同步，没有索引文件（除非你要）。每一条知识就是一个 Markdown 文件，你能用任何编辑器打开、用 `git log -p` 审阅、用 `rsync` 搬到别的机器。

---

## 它做什么

| 能力 | 说明 |
| --- | --- |
| **自动沉淀** | 每轮对话结束时异步提炼：正文过长且非寒暄时生成一张「要点卡」，其中成形的代码块各自成为一张「片段卡」。全程不阻塞、不影响对话。 |
| **自研去重** | 两级判定：先用 MinHash 签名（256 槽）快速筛掉明显无关的卡，再对候选做**精确的词元集合比较**（Jaccard + 包含度）。精确重复总是合并；近似重复按配置合并或另存并互链。 |
| **CJK 检索** | 自研分词：中文/日文按**字符二元组**切分（短串额外保留整串），拉丁/数字/谚文按词切分，复合标识符（`ctx.webServer.save`）整体保留并同时展开子词。检索用 BM25，并对字面命中与顺序命中加权。 |
| **可 git 管理** | 一张卡一个文件、文件名带日期与标题、YAML frontmatter 字段顺序固定、写入走原子替换（临时文件 + rename）。可选自动提交。 |
| **模型工具** | `brain_recall` / `brain_save` / `brain_list` / `brain_capture` / `brain_stats` / `brain_forget`，同时注册一段系统提示词，让模型知道该在什么时候回忆、什么时候保存。 |
| **图形化知识库** | 设置页 → 第二大脑 → 知识库：中文检索、标签与类型筛选、卡片列表、所见即所得的卡片编辑器。 |
| **交互式知识图谱** | SVG 力导向图：图例按标签/类型过滤、时间维（月度直方图 + 日期区间）、滚轮缩放、Shift 拖拽平移、拖拽节点、**框选多选**、合并、导出与导入。 |

## 安装

```bash
# 在 DSH 里（推荐，会写进 profile 的 bundle 列表）
#   设置 → 插件 → 安装 bundle → 选择本目录，或：
# 手工：把包放进 profile 并登记一行
```

手工安装（等价做法）：

1. 把本目录放到 profile 能解析到的位置（例如 `~/.dsh/profiles/<profile>/node_modules/dsh-second-brain`，或 `pnpm add /path/to/dsh-second-brain`）。
2. 在 profile 的 `cordis.patch.yml` 末尾加入：

   ```yaml
   - insert:
       - id: second-brain
         name: 'dsh-second-brain'
   ```

3. 重启 / 重新加载 DSH。宿主半会在启动日志里打印一行 `[dsh-second-brain] 已挂载，知识库：…`。

> 客户端半是浏览器插件，改完之后刷新页面即可；只有在 `pnpm run dev:web` 同时运行时才会免刷新热更。

## 使用

### 在对话里

模型会在需要回忆时调用 `brain_recall`，在产出可复用结论时调用 `brain_save`。你也可以直接说：

- 「记住：这个项目的知识库放在 `~/kb`，用 git 管理」
- 「上次我们讨论的插件双半结构是什么？」
- 「把这轮讨论沉淀一下」

### 设置页

**设置 → 第二大脑**（`settings.section` 页，可与其它插件页面并列）：

- **知识库**：检索、筛选、编辑、新建、删除。
- **知识图谱**：见下。
- **设置**：知识库目录、采集策略、去重阈值、git 操作、可选的模型提炼。

### 知识图谱的操作

| 操作 | 手势 |
| --- | --- |
| 框选多个节点 | 在空白处按住左键拖出矩形 |
| 追加选择 | 框选或点击节点时按住 `Shift` |
| 平移画布 | `Shift` + 拖拽（或用中键拖拽） |
| 缩放 | 滚轮 |
| 拖动单个节点 | 直接拖节点 |
| 过滤 | 右侧图例点击标签/类型；点击月度直方图的柱子按整月过滤 |

图例、时间维与框选可以叠加：图例决定「哪些标签/类型可见」，时间维决定「哪个时间段」，框选决定「当前选中哪些」，选中集合再喂给合并 / 导出 / 删除。

## 知识卡格式

```markdown
---
id: kb-20261013-a1b2c3
title: 插件双半结构
kind: fact
createdAt: 2026-10-13T01:23:45.000Z
updatedAt: 2026-10-13T01:23:45.000Z
hash: 8f0c1e2d4a5b6c7d-142
tags:
  - dsh
  - 插件
provenance:
  - session-abc#/Users/me/project#turn7
links:
  - kb-20261012-9f8e7d
---

宿主半导出 `apply` / `inject`，浏览器半是一个 `__ModuleLoader__` 工厂。
```

`kind` 取值：`fact`（事实）、`procedure`（步骤）、`decision`（决策）、`snippet`（代码片段）、`note`（笔记）。

文件落在 `<知识库>/cards/YYYY-MM-DD-标题--<id后缀>.md`。合并时如果标题变了，文件会改名——`git` 会把它识别为一次重命名而不是删除加新增。

## 配置

配置持久化在 `$DSH_HOME/second-brain/config.json`（默认 `~/.dsh/second-brain/config.json`）。

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `vault` | `$DSH_HOME/second-brain/vault` | 知识库根目录。支持 `~` 与相对路径（相对 `$DSH_HOME`）。 |
| `capture` | `heuristic` | `heuristic`（默认，确定性）/ `llm`（调用模型，失败自动回退）/ `off`。 |
| `minChars` | `400` | 助手回复短于该长度就不生成要点卡；代码片段仍会单独成卡。 |
| `minCodeLines` / `minCodeChars` | `3` / `100` | 代码块成卡的门槛，二者取「或」。 |
| `maxCardChars` | `6000` | 单卡正文上限。 |
| `tagsLimit` | `6` | 自动标签数量上限。 |
| `dedupeThreshold` | `0.42` | 判为重复的词元 Jaccard 阈值。见下方「阈值是怎么定的」。 |
| `relatedThreshold` | `0.18` | 建立关联边的阈值。 |
| `autoMergeDuplicates` | `true` | 关闭则近似重复另存并互链（精确重复仍会合并）。 |
| `heuristicFallback` | `false` | `llm` 模式下模型不可用时，是否回退到确定性提取器。默认关闭＝跳过本轮。 |
| `linkRelated` | `true` | 为相关卡片自动建立关联。 |
| `gitAutoCommit` | `false` | 每次写入后自动 `git add -A && git commit`。 |
| `writeIndexFile` | `false` | 额外生成 `index.json`（默认关闭，让仓库里只有手写的 Markdown）。 |
| `llmProvider` / `llmModel` | 空 | 留空则沿用当前默认模型。 |

## 安全边界

这些路由由宿主进程的 Web 服务器提供，**前面没有任何鉴权层**，所以插件自己守门：

- **写操作必须带 `content-type: application/json`。** 跨站页面能免预检发出的只有 `text/plain`、`application/x-www-form-urlencoded` 这类「简单请求」，它们一律被 415 拒绝；而 `application/json` 会触发预检，这台服务器从不回应预检。这一条就把跨站写操作挡在门外。
- **带 `Origin` 的写操作必须同源。** 浏览器对同源 POST 也会发 `Origin`，它与 `Host` 不符时返回 403。
- **导入的 `id` 不被信任。** `id` 可以来自任意 bundle，而文件名是从它派生的——早期版本直接把 `id` 的尾段拼进文件名，于是 `id: "../../../owned"` 能把 Markdown 写到知识库之外的任何位置。现在 id 只接受 `[A-Za-z0-9_]{1,40}`，不符合就退回内容哈希；`store.js` 里还有第二道 `resolveCardPath()` 断言，任何逃出 `cards/` 的路径都会抛错。
- **`mode: "replace"` 必须显式确认。** 它要同时带 `mode: "replace"` 和 `confirm: "replace"`，而且 bundle 里必须有合法且非空的 `cards` 数组——否则拒绝执行。早期版本先清空知识库、再发现 bundle 不可用，一个畸形请求就能毁掉整个库。
- **错误码区分开**：body 不是合法 JSON → 400，超过 32 MiB → 413，未知路由 → 404。

## 模型提炼失败时会发生什么

`capture: 'llm'` 下有三种结局，区分得很清楚：

| 模型的回答 | 处理 |
| --- | --- |
| 一个 JSON 数组，可能为空 | **尊重它。** 空数组 = 「本轮没有值得沉淀的内容」，本轮跳过，**不跑启发式**。 |
| 数组被 `maxTokens` 截断 | **当作部分答案，不当作失败。** 把截断点之前**完整的对象**全部救回来（字符串感知的括号扫描，正文里的 `}` 和转义引号不会骗到它）。 |
| 完全无法解析（纯散文、超时、provider 报错） | **跳过本轮**，知识库保持干净。想恢复「换启发式顶上」的旧行为，把 `heuristicFallback` 打开即可。 |

最后一条默认关闭是有原因的：确定性提取器在长回复里**总能**找到东西——一张以你的消息为标题的卡，加上每个代码块一张卡。那正是这套模式想避免的噪声，所以拿它去顶一次失败的模型调用是错的默认值。

第二条是踩出来的：长回合会让模型的 JSON 输出撞上 token 上限，旧版把「截断」当成「失败」→ 回退启发式 → 生成一批以用户消息为标题的卡。`maxTokens` 也从 1500 提到 3000，降低撞上的概率。

## 已知限制

- **外部改动靠 mtime + size 判断新鲜度。** 用 `cp -p` / `tar -x` / `rsync -t` 恢复出来的文件若时间戳与大小都没变，插件不会察觉，需要 `POST /second-brain/reindex`（面板设置页有「重新索引」按钮）强制重扫。直接编辑源文件（正常写文件流程）会更新 mtime，能被立刻发现。

## 阈值是怎么定的

去重阈值不是拍脑袋来的，而是量出来的。在中文卡片上，用同一套分词统计三类真实卡片对的相似度：

| 关系 | 词元 Jaccard |
| --- | --- |
| 同主题、内容不同（「力导向图布局」vs「知识卡格式」） | 0.03 – 0.12 |
| 同一主题、逐句重写 | 0.29 – 0.57 |
| 同一知识的增补版 / 近乎逐字重复 | 0.54 – 0.81 |

「同主题但内容不同」和「同一知识换个说法」之间有一道很宽的空档，`dedupeThreshold` 就落在空档里（默认 0.42）。包含度是第二条通路：正文完全涵盖另一张卡时（containment ≥ 0.85），即使 Jaccard 被多出来的段落拉低也判为重复——「同一份知识 + 多写了一段」本来就应该合并。

## 什么时候会采集、采集成什么

每轮对话结束时异步跑一次（`agent/turn-stopping`，fire-and-forget，不阻塞也不影响对话）：

1. **要点卡**来自这一轮的**最终回答**。多步任务里中间那些「我先看看…」「现在我来…」是过程叙述，不是知识，因此不参与成卡——这是踩过的坑：早期版本把整轮的助手文本拼起来，结果抓到一堆过程叙述。
2. **片段卡**来自这一轮**所有**助手消息里的成形代码块（第 3 步写的代码和最后一步写的一样值得复用）。
3. 用户明确说「记住…」时，额外把用户自己的原话存成一张 `note`。
4. **DSH 注入的机器消息会被剔除。** 运行时上下文、时间采样、模型切换通知、队友转发、子代理结束通知——这些**全都以 user 角色投递**，但只有 `source.kind === "user"` 才是人在说话。判定读信封而不是猜文本：早期版本靠一张前缀清单（`Time sampled while preparing turn…` 等），结果 `[model changed: …]` 这种新形态一出现就漏了，生成一批以通知为标题的垃圾卡。信封缺失时（种子会话、单测里手搭的消息）才回退到前缀清单。

## HTTP 接口

浏览器半通过插件自己的 `/second-brain` 前缀路由与宿主通信（手写插件拿不到 Typert 生成的 `@Remote` 代理，所以走 HTTP，和官方音乐插件同一套路）。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/ping` | 存活探测（含 `version`，可确认宿主实际加载的是哪个构建） |
| GET | `/overview` | 配置 + 统计 + 标签 + 类型分布 |
| GET/POST | `/config` | 读取 / 合并写入配置 |
| GET | `/list?q&tag&kind&limit&offset` | 列表（无 `q` 时按时间倒序，有 `q` 时按相关度） |
| GET | `/search?q&tag&kind&limit` | 检索，带片段 |
| GET/POST | `/card` | 读取单卡 / 保存（带 `id` 即更新） |
| POST | `/delete` | `{ ids: [...] }` |
| POST | `/merge` | `{ ids: [...], title? }` |
| GET | `/graph` | 节点 / 边 / 标签图例 |
| GET | `/export?ids&download=1` | 导出 bundle（JSON） |
| POST | `/import` | `{ bundle, mode: 'merge' \| 'replace' }` |
| POST | `/reindex` | 强制重扫目录 |
| POST | `/git` | `{ action: 'init' \| 'commit' \| 'status' }` |
| POST | `/capture` | `{ sessionId, whole? }` 手动采集某个会话 |

## 设计取舍

- **为什么不用 `ctx.fs` 写文件？** 宿主 `ctx.fs` 会在会话工作区策略下拦截写入，知识库一旦落在工作区之外就会被静默丢弃。所以卡片 IO 直接用 `node:fs`（与官方音乐插件持久化自身状态的做法一致），并采用「临时文件 + rename」的原子写，避免崩溃截断文件。
- **为什么去重是两级？** MinHash 的估计误差让「接近重复」和「无关」在阈值附近难以区分；而个人知识库的卡片都很短，精确的词元集合比较完全跑得起。于是签名只做预筛（把绝大多数无关卡一次性排除，且不需要分词），判定交给精确比较。
- **为什么还要包含度？** 「同一份知识 + 多一段补充」的 Jaccard 会明显下降，但包含度接近 1——那仍然是重复，应该合并而不是新建。
- **为什么按二元组切分中文？** 不引入分词器、不依赖词典，对「知识图谱 / 图谱可视化 / 知识卡」这类查询的召回与排序都足够好；再叠加字面命中加权，短查询也能稳定命中。
- **为什么自动采集是启发式优先？** 采集绝不能拖慢或打断一轮对话，也不能因为没配模型就失效。模型提炼是可选增强，任何失败都静默回退。
- **为什么客户端不打包？** 手写 `__ModuleLoader__` 工厂 + `React.createElement` 是官方插件验证过的零构建路径；不引入 JSX/CSS 管线，插件就能被直接复制、审阅和改动。

## 开发

```bash
npm test        # node --test test/*.test.mjs
```

测试覆盖（93 项）：

- **分词与检索**：CJK 二元组、拉丁/谚文词、复合标识符展开、停用词、BM25 排序与标签/类型/时间过滤、片段与顺序命中。
- **去重**：MinHash 估计、精确 Jaccard/包含度、`compareCards` 的四种判定、空 hash 不算重复、跨进程签名稳定性，以及**基于真实卡片对量出的阈值标定**（同主题不同内容必须保持 distinct）。
- **id 与文件名**：`safeIdToken` 对恶意 id 的归一化、8 位 id 后缀、`resolveCardPath` 的越界拒绝、id 碰撞时另铸新 id 而不是覆盖。
- **卡片编解码**：含引号/换行/`---` 的标题往返、非法 frontmatter 报错而非猜测。
- **仓库**：CRUD、mtime 缓存对外部编辑的响应、原子写、去重合并、合并后的重命名与孤儿清理、导入导出、git init/commit、坏文件不致命。
- **宿主半**：`apply()` 注册面、六个工具的执行、全部 HTTP 路由（含 404/400/403/415 分支）、配置写入、自动采集的幂等与 `force`、模型提炼的解析与回退。
- **安全**：恶意 `id` 无法逃出 `cards/`（HTTP 层与仓库层各测一遍）、`replace` 缺确认或空 bundle 时拒绝且不破坏现有数据、非 JSON 与跨站写操作被拒、畸形 JSON 返回 400。
- **客户端半**：包在假 ModuleLoader 下的加载、槽位注册与样式注入、力导向布局的确定性/收敛性/边界、图例与时间过滤、框选矩形归一化、**viewBox 缩放/letterbox 与平移缩放变换的坐标换算**（含退化尺寸不产生 NaN、缩放锚点不动点性质），以及**整棵设置页组件树的渲染冒烟测试**（用会真正递归渲染函数组件的 React shim）。

代码结构：

```
lib/core.js     纯逻辑：分词、哈希、MinHash、BM25、卡片编解码、图谱模型、合并、导入导出
lib/extract.js  纯逻辑：把一轮对话提炼成知识卡草稿（含代码片段成卡）
lib/store.js    仓库：Markdown 落盘、mtime 缓存、检索索引、去重比较、git
lib/index.js    宿主半：Cordis 插件（配置、自动采集、工具、HTTP 路由、提示词）
lib/client.js   浏览器半：ModuleLoader 工厂 + 设置页（知识库 / 知识图谱 / 设置）
```

## 改完之后怎么生效

- **浏览器半**（`lib/client.js`）：刷新页面即可；只有 `pnpm run dev:web` 同时运行时才免刷新。
- **宿主半**（`lib/index.js`、`lib/core.js`、`lib/store.js`、`lib/extract.js`）：**必须重启 DSH**。在插件管理里禁用再启用同一个插件行**不会**重新加载模块——Node 的 ESM 缓存按 URL 缓存，Loader 复用它。这点值得记住：`/ping` 的 `version` 字段就是为了让你一眼看出「我改的东西到底生效了没有」。
